# Sample reproduction and the label barrier

What `make reproduce-small` runs, what it pins, and every stage change made so a
committed synthetic sample can drive the ported chain without the research archive.

## The sample

`data/sample/` (4.3 MB) is fully synthetic, generated by `tools/make_sample.py` with
`numpy.random.default_rng(20260913)`; `data/sample/README.md` lists the files and the
world they describe. Counts: 60 players; seasons 2011–2020; 250 events (25 per season:
4 `G` best-of-five draws of 32, 6 `M` draws of 32, 15 `A` draws of 16); 5,350 panel rows
in the `format_corrections` schema; 4,815 base rule rows (2011–2019); 31,320 weekly
ranking rows in a Sackmann-layout tarball with one match file per season. The last
season's final event carries a new event code so the rule carry-forward exercises its
tour-default path (520 carried rows, 15 defaulted, 0 refused). The generator re-pins every
sample hash in `configs/chains/sample_atp.json`; `tests/test_reproduce_small.py` checks
the committed files are exactly what the generator emits.

## Stages exercised

The chain config skips the seven stages that bind pinned real-world evidence by hash
(`bridge`, `archive_panel`, `join`, `event_carry_forward`, `prepare_panel`,
`format_corrections`; unit tests cover them) and runs, from the sample panel:
`rule_mapping`, `sr02_replay`, `sr03_calibration`, `rankings`, `edition_index`,
`features`, `sidecar`, `predictor_config`, `preflight`, `pipeline`, `barrier`,
`reporting_config`, `report`. Bundles `base` and `full`, learner `hgb`, no tier stages.
Year plan: panel and features to 2020, targets 2018–2020, calibration two years back,
history floor 2011, five-year training window. `stage_config_overrides` point
`rule_mapping`, `sr02_replay`, `sr03`, `features` and `sidecar` at `data/sample/panel.csv`
and give `rankings` the synthetic tarball; every later stage reads what the earlier
sample stages produced.

`tennislab reproduce-small` (`src/tennislab/reproduce.py`) copies the sample and its chain
config into a fresh workspace `data/runs/reproduce_small/`, runs `write-configs`,
`dry-run` and `run --include-report` through `tennislab.chain.runner.main`, and compares
the report against `data/sample/expected.json` to 1e-9. `--pin` rewrites the pinned file
from a run.

## Runtime

`make reproduce-small`: about 35 s on the development laptop (sr02_replay 15 s, pipeline
14 s, everything else under 2 s each). `tests/test_label_barrier.py`: about 65 s (the
chain to `reporting_config` once, the pipeline once more in-process, the report refusal).
`tests/test_reproduce_small.py`: under 3 s. `tests/test_cli.py::test_reproduce_small_runs`
now runs the full reproduction as well (about 35 s); it is outside this note's write
boundary and could move into `test_reproduce_small.py`.

## Stage changes and re-verified equivalence

Each change keeps the frozen real configs' behaviour; the equivalence harness was rerun
on `TIER01/attempt_002` and `WTA02/attempt_002` for every changed stage and the
identical/different counts in `docs/equivalence/<run>/<stage>.json` are unchanged (only
provenance leaves moved: the changed module's code-receipt hash, timestamps, fit timings).

| Module | Change | Why the sample needed it | Re-verified |
|---|---|---|---|
| `panel/rankings.py` | `ArchivePin` (path, sha256, member root, commit) read from the stage config's optional `archive` object; the default is ARCHIVE01 exactly as before, `--archive` overrides it | the stage hard-coded ARCHIVE01's path, hash and member root | TIER01 36/38, WTA02 38/38, unchanged; the JSON results are byte-identical to the committed ones |
| `features/base.py` | a blank `a_won` is an unresolved outcome (`Record.a_won = None`): the row is a target, updates no result-Elo state, and its `labels.csv` row carries a blank; the written-output check expects the blank | label-barrier test (point 5) | TIER01 7/10, WTA02 8/10, unchanged |
| `dynamics/calibration.py` | `load_dataset` records no outcome for a played row whose `a_won` is blank (it is predicted, never trained on or scored) | label-barrier test | TIER01 12/13, WTA02 13/14, unchanged |
| `chain/configs.py` | `label_binding`: the predictor config takes `labels.csv`'s hash from the features stage's manifest (after checking that manifest binds the feature file) instead of hashing the file; a labels path that is not the features stage's own `labels.csv` is refused | structural test: `predictor_config` must not open the label file | TIER01 1/2, WTA02 1/2, unchanged; side config differs in the same six provenance leaves as before |
| `models/pipeline.py` | `load_frozen_run_config` records the label file's bound hash without opening it; `LabelHistory.selected` checks the hash before every read as before | structural test: `preflight` must not open the label file | preflight 1/2 both runs; pipeline TIER01 407/740, WTA02 273/576, unchanged |
| `evaluation/report.py` | a blank `a_won` in `labels.csv` is refused with `unresolved outcome (blank a_won) at <key>: the report scores no target year whose outcomes are not yet known` | the report must refuse, not score, the unknown year | TIER01 13/16, WTA02 13/16, unchanged |
| `features/sidecar.py` | `validation.json` reads `sr02_present`/`sr02_missing` with a zero default (the sample has an SR02 row for every panel row, so the counter never created `sr02_missing`) | the stage raised `KeyError` on the sample | TIER01 8/9, WTA02 8/9, unchanged |

No change to `chain/runner.py`, `chain/common.py`, `config.py`, `tools/equivalence.py`,
`sources/bridge.py`, `panel/crosswalk_v2.py`, `ratings/tier_*.py` or
`features/tier_block.py`.

## Label barrier (RB3)

`tests/test_label_barrier.py` regenerates the sample with every 2020 `a_won` blank (the
generator's `--unknown-outcomes-final-year`), drives the chain exactly as
`reproduce-small` does, and checks: every stage before `report` exits 0 and writes its
outputs, and `chain verify` passes; `labels.csv` carries a blank for every 2020 row and
0/1 elsewhere, and no feature row's `elo_latest_source_date` reaches 2020;
`sr03_calibration` persists 2020 predictions and scores none of 2018–2020
(`scoring_boundary.json`); the pipeline's `selection_complete.json` is complete for 2020
with `outer_target_outcomes_scored: false`; the `report` stage exits non-zero with the
message above and writes no `primary.json`. The pipeline is then run once more in-process
with `LabelHistory` replaced by a recording subclass: every read declares one of
`training_fit`, `past_selection_calibration`, `past_market_calibration`, its ceiling is
below 2020 (2015–2019 for the training fits, 2017–2019 for the selection and market
calibrations), and no requested key's season exceeds its ceiling.

Structural check: with `labels.csv` made unreadable (mode 0) after the `features` stage,
`sidecar.run`, `configs.main(["predictor", ...])` and `pipeline.main(["preflight", ...])`
complete in-process. The chain driver itself cannot run those stages with the file
unreadable because `verify_earlier` hashes every earlier output before each stage; the
check therefore calls the three programs directly.

## Not done, and things to know

- The `rankings` stage reads winner/loser ids from the tarball's match files for its
  retrospective join statistics; the label-barrier test blanks the panel's outcomes only,
  as the brief specifies, so the synthetic 2020 match file still names winners. The stage
  computes no score from them.
- The chain runner emits stage configs for skipped stages too, so the sample chain config
  carries a placeholder `inputs.correction_proposals` (pointing at `design.md`, never
  run) and `inputs.ranking_lookup_module` as a `module` binding with no `path`; both are
  labelled in the config.
- `make lint` and `make test` (327 passed, 1 skipped, 1 min 42 s) pass on the working tree
  with these changes; neither needs `TENNISLAB_ARCHIVE`.
- Bootstrap replicates (2,000) and the HGB candidate menu are part of the frozen settings
  contract and are not configurable per chain; the sample is small enough that neither
  needed to be.
